## Algebra-first build

The current build uses REL for page content, projection configuration, presentation declarations and process configuration. It still requires MJS for page construction, runtime behaviour generation, HTML emission and assurance. The previous module registry did not execute algebra-defined modules and has been removed. The JavaScript build remains the working migration baseline; passing its site checks does not establish bootstrap completion.

The intended execution chain is: minimal Temple seed → executable algebra modules → application facts → rendered site. Module implementations must be executable process/expression graphs that the seed evaluates. DOM construction, CSS projection, browser/worker behaviour and assurance must hydrate from those graphs without importing their current MJS implementations. The seed owns generic execution and explicit host ports; module names and paths alone do not supply behaviour.

Completion requires a clean build with the MJS module tree absent, using only the seed, algebra definitions, application facts and assets. It must render all pages, execute the declared signup and menu transitions, and run assurance through the same algebra. A changed algebra rule must change output without editing the seed; unknown operations and missing definitions must refuse execution. The existing seed/runtime implementation and the exact host-port boundary must be identified and verified before this can be claimed as implemented.

Run `node scripts/generate-site-manifest.mjs` to run the semantic-REL → Claimipedia grammar → DOM-REL → HTML-IR → HTML pipeline plus the presentation-REL → CSS projection, or `node scripts/build-site.mjs` to produce the publishable `dist/` package. The build refuses to publish when projection, shared navigation, declared routes, page metadata or declared content anchors drift. `dist/` is output, not source.
